### 1. MiniCPM-o 4.5: Towards Real-Time Full-Duplex Omni-Modal Interaction
- **作者**: Junbo Cui, Bokai Xu, Chongyi Wang, Tianyu Yu, Weiyue Sun, Yingjing Xu, Tianran Wang, Zhihui He, Wenshuo Ma, Cai 等
- **机构**: 未知（论文未明确给出，HF 社区指向 OpenBMB / 清华系）
- **链接**: [arXiv](https://arxiv.org/abs/2604.27393) | [PDF](https://arxiv.org/pdf/2604.27393)
- **来源**: 🔥 HF Trending，⬆️ 71
- 📒 **笔记**: [[MiniCPM-o-4.5]]

![](https://arxiv.org/html/2604.27393v1/media/radar_minicpmo4.5.png)

- **核心方法**: 输入是视频流 + 音频流 + 文本，输出是文本 + 流式语音，目标是让一个 9B 模型能"边看边听边说"。核心组件：(1) [[流式多模态编码器]]把 vision/audio 切片喂入；(2) LLM backbone 做 Omni 理解与文本生成；(3) interleaved speech token decoder 做流式语音输出。关键是 Omni-Flow，把 omni-modal 输入输出对齐在共享时间轴上，以此把 turn-based 改成 full-duplex 时间对齐过程，并支持模型主动行为（提醒、点评）。号称 12GB RAM 边缘设备可跑实时全双工。
- **对比方法/Baselines**: [[Gemini-2.5-Flash]]（视觉语言对标）、[[Qwen3-Omni-30B-A3B]]（Omni 理解和语音生成对比）。架构思路与 [[GPT-4o]]、[[Moshi]] 同属 omni-modal 全双工流派
- **借鉴意义**: 对做全双工 Speech LLM 的人这是必读。Omni-Flow 把 perception/response 阶段融合成一条时间轴的思路，比传统"听完一段→说一段"的 cascade 干净；端侧 9B / 12GB RAM 的工程优化也可借鉴
- **锐评**: HF 71 upvotes，号称 Gemini 2.5 Flash 级 VL 能力 + 超 Qwen3-Omni-30B-A3B 的 Omni 理解 + 更强的语音生成，听上去像把所有 SOTA 基线一巴掌打趴。但摘要里没给出端到端响应延迟、interruption 恢复时间、barge-in 真实评测等"全双工灵魂指标"，这些在用户感知里比 benchmark 分数重要 100 倍。"proactive behavior"（主动提醒）听起来很厉害，问题是怎么避免它在你思考时插嘴——摘要没讲。等真机 demo。🔥

### 2. OmniFlatten: An End-to-end GPT Model for Seamless Voice Conversation
- **作者**: Qinglin Zhang, Luyao Cheng, Chong Deng, Qian Chen, Wen Wang, Siqi Zheng
- **机构**: Alibaba Inc.
- **链接**: [arXiv](https://arxiv.org/abs/2410.17799) | [PDF](https://arxiv.org/pdf/2410.17799)
- **来源**: 🔥 HF Trending，⬆️ 13
- 📒 **笔记**: [[OmniFlatten]]

![](https://arxiv.org/html/2410.17799/x1.png)

- **核心方法**: 输入是用户语音流，输出是模型语音流（同时支持文本），目标是端到端 full-duplex 对话。把文本 LLM backbone 不改架构、靠多阶段后训练适配成 speech-text dialogue LLM：(1) modality alignment、(2) half-duplex dialogue learning、(3) full-duplex dialogue learning。关键 trick 是 [[flatten 操作]]——把多模态多任务数据展平成统一序列，让架构与训练统一。强调能建模 interruption / backchannel / overlapping speech。
- **对比方法/Baselines**: 摘要+ method_summary 提到 [[Qwen-Audio2]]（仅语音输入文本输出）、[[SALMONN]]（同上）、[[SpeechGPT]]、[[LauraGPT]]、[[Mini-Omni]]、[[LLaMA-Omni]]、[[GLM-4-Voice]] 作对比。CosyVoice 也在 method_names 里，可能用作 TTS 模块或基线
- **借鉴意义**: 想做"基于现成文本 LLM 改造成 speech LLM"的工程团队，这是参考路径之一：分阶段、不改架构、用 flatten 喂数据。比从头训 Moshi-style audio-token 模型门槛低
- **锐评**: 立意正确，方法保守。"flatten + 不改架构"听起来像把语音 token 当成多语言 token 接上 LLM 的常见操作，能不能解决全双工真正的难点（毫秒级 reaction、overlapping speech 解纠缠、turn-taking 的语义判定）摘要没给硬数字。和 [[Moshi]] 那种从底层 audio token 重塑模型相比，"flatten" 路线更便宜但天花板可能更低。HF demo 站在线，先去 omniflatten.github.io 听一下再下定论。⚠️

### 3. VibeVoice Technical Report
- **作者**: Zhiliang Peng, Jianwei Yu 等（Microsoft Research，含 Fuwei 为联系人）
- **机构**: Microsoft Research
- **链接**: [arXiv](https://arxiv.org/abs/2508.19205) | [PDF](https://arxiv.org/pdf/2508.19205)
- **来源**: 🔥 HF Trending，⬆️ 170
- 📒 **笔记**: [[VibeVoice]]

![](https://arxiv.org/html/2508.19205/x1.png)

- **核心方法**: 输入是长文本（含多个说话人），输出是连贯长篇多说话人语音（最长 90 分钟，最多 4 个 speaker）。骨干是 [[next-token diffusion]]——一种把连续数据建模成"AR 生成 latent vector + diffusion 解码"的统一范式。核心 contribution 是新的 [[连续语音 tokenizer]]，相比 [[EnCodec]] 把数据压缩提升 80×，但保持可比的重建质量。这个超低码率 token 让 LLM 在 64K context 内塞下 90 分钟语音。指标用 WER / SIM / PESQ。
- **对比方法/Baselines**: [[EnCodec]]（核心对比对象，压缩率 80×）；与"开源和闭源对话模型"在长篇多说话人合成上对比（具体 NotebookLM / Bark / Tortoise 摘要未点名）。next-token diffusion 路线与 [[VALL-E]]、[[Voicebox]] 形成对照
- **借鉴意义**: 对做 TTS / Audio Codec 的人，80× 压缩同时保持音质这件事如果属实，会改变所有下游 LLM 用 audio token 的工程经济学。next-token diffusion + 连续 latent 也是当前学术界争论的方向，值得把架构图和 tokenizer 细节扒一下
- **锐评**: 170 upvotes 的热度配 Tech Report 的体裁，表面看像 Microsoft 的市场动作。但真正值得盯的是两件事：(1) 80× 压缩的具体码率是多少？vs EnCodec 的"comparable performance"是哪个域？(2) 90 分钟 / 4 speaker 的长篇一致性是怎么验证的——人类评估了多少人？说话人切换次数？没解答这两点，"vibe" 这个词可能就是字面意思，氛围。🔥

### 4. SemaVoice: Semantic-Aware Continuous Autoregressive Speech Synthesis
- **作者**: Huimeng Wang 等
- **机构**: The Chinese University of Hong Kong, Tsinghua University, SenseTime Research
- **链接**: [arXiv](https://arxiv.org/abs/2605.16964) | [PDF](https://arxiv.org/pdf/2605.16964)
- **来源**: 📄 arXiv 关键词检索
- 📒 **笔记**: [[SemaVoice]]

![](https://arxiv.org/html/2605.16964v1/x1.png)

- **核心方法**: 输入文本 + reference speech，输出 zero-shot TTS 语音。核心论点：现有 continuous AR TTS 的 latent 是 reconstruction-driven，与 semantic-prosodic 建模不匹配，导致 AR 误差累积。SemaVoice 用 [[Speech Foundation Model (SFM) 引导对齐]] 改造连续语音表示，使其同时捕捉局部语义一致性与全局结构。再用 [[patch-wise diffusion head]] 在 AR 框架下解码出语音。在 Seed-TTS 上 EN WER = 1.71%。
- **对比方法/Baselines**: [[Seed-TTS]] 基准上的 SOTA 开源系统（具体名单需看正文）。继承的方法谱系包括 SFM（HuBERT / WavLM / Whisper 一类）、连续 AR TTS（接近 [[MELLE]] / [[Voicebox]] 的连续 latent 思路）、扩散头（与 [[NaturalSpeech-3]] 的 head 结构有竞争关系）
- **借鉴意义**: 做 zero-shot TTS / continuous AR TTS 的人值得读。"AR latent 应该承载语义而不仅是重建"这一点是当前 continuous-token TTS 的关键痛点，SFM 引导对齐是合理解法
- **锐评**: 出发点对：reconstruction-driven latent 在 AR 里确实容易让模型沉迷低频纹理。但摘要里只给了 Seed-TTS EN WER = 1.71%，没给说话人相似度（SIM）、长篇稳定性、CER 这些 zero-shot TTS 该有的核心指标，更没和 [[F5-TTS]]、[[CosyVoice 2]]、[[MELLE]] 这种 2024–2025 的强基线做明确对比。"highly competitive" 是个模棱两可的措辞——比谁、比哪些项、差几个百分点，都得正文里找。🫠

### 6. JSPG: Dynamic Dictionary Filtering via Joint Semantic-Pinyin-Glyph Retrieval for Chinese Contextual ASR
- **作者**: Shilin Zhou, Zhenghua Li 等
- **机构**: School of Computer Science and Technology, Soochow University
- **链接**: [arXiv](https://arxiv.org/abs/2605.16896) | [PDF](https://arxiv.org/pdf/2605.16896)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2605.16896v1/x1.png)

- **核心方法**: 输入是 N-best ASR 假设 + 大规模关键词词典，输出是过滤后的小子集，喂给下游 contextual ASR。核心动机：中文 ASR 的错误经常是同音/近音替换，破坏语义但保留语音线索，导致语义检索失效。JSPG 联合三路信号——[[语义]]、[[拼音]]、[[字形]]——做检索；引入扩展的 [[Smith-Waterman 算法]] 在 N-best 序列与关键词之间算字符级相似度。在 Aishell-1 / RWCS-NER 上验证。
- **对比方法/Baselines**: 单特征 baseline（仅语义、仅拼音、仅字形），下游 contextual ASR 模型未点名（猜测 [[CLAS]] / [[NAM-Encoder]] / [[CIF-NN]] 一类）
- **借鉴意义**: 对做中文流式/contextual ASR 的人非常对口。拼音 + 字形 + 语义这种"汉字三路特征"在 ASR 里是直觉但实际系统经常只用其一；联合检索 + Smith-Waterman 能装进现有 pipeline 不破坏架构
- **锐评**: 直观、对症、实用。但有点担心：(1) 拼音特征的好处来自同音错误，但在严肃部署里大词典（几十万）下是否真比 BM25 + 简单后过滤强？需要看消融； (2) Smith-Waterman 字符级是 O(n·m)，几十万词典下检索代价可能不可接受，论文应该报告检索延迟。👀

### 9. From Flat Language Labels to Typological Priors: Structured Language Conditioning for Multilingual S2ST
- **作者**: Yu Pan, Yang Hou, Xiongfei Wu, Liang Zhang, Yves LE TRAON, Lei Ma, Jianjun Zhao

- **核心方法**: 输入是源语言语音，输出是目标语言语音（many-to-one）。核心论点：现有 S2ST 把 source 语言当成 flat label embedding，浪费了语言之间的类型学结构。S2ST-Omni 2 把语言条件化做三层：(1) [[typology-informed hierarchical language encoding]]、(2) [[dynamically-gated language-aware Dual-CTC]]、(3) [[typology-aware LLM prompting]]。在 [[CVSS-C]] 上 BLEU/COMET/ASR-BLEU/BLASER 2.0 平均最优；3 小时日英监督下也能用类型学先验拿到收益。
- **对比方法/Baselines**: 摘要里说"代表性 S2ST 方法"，没点名。SpeechLLM 路线的 S2ST 同行包括 [[Seamless-Expressive]] / [[CosyVoice S2ST]] / [[GenTranslate]] 等
- **借鉴意义**: 做多语种 S2ST、SpeechLLM 多语种适配的人值得参考。"语言先验从 flat embedding 变成结构化类型学特征"这个思想可迁移到 multilingual TTS 与多语种 ASR
- **锐评**: 立意有新意，工程也铺得密（三层 conditioning + Dual-CTC + LLM prompting），但这种"叠 buff"的方法论容易踩到 ablation 解释不清的坑——三层都对最终 BLEU 都有贡献吗？还是只有 typology-aware prompting 在工作？摘要说"complementary benefits"是好兆头，但 3 小时日英数据上的"useful inductive bias"可能也包含 LLM prompt 在 zero/few-shot 起的作用，与 typology 关系多大要看正文。👀

### 10. Analyzing Error Propagation in Korean Spoken QA with ASR-LLM Cascades
- **作者**: 未明确
- **机构**: Korea Institute of Culture Technology
- **链接**: [arXiv](https://arxiv.org/abs/2605.17443) | [PDF](https://arxiv.org/pdf/2605.17443)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2605.17443v1/figures/pipeline.png)

- **核心方法**: 输入是带噪声的韩语口语 QA，目标是分析 ASR 错误如何传播到下游 LLM 答题。在 7 档 SNR 下合成噪声，让 CER 在 0.03–0.50 间扫描；测多个 LLM 的 QA 表现；并附带对照实验：用一个匹配语言 backbone 的 [[Large Audio Language Model]] (LALM) 直接吃语音，与 ASR-LLM cascade 比。结论：(1) 不同性能 LLM 的相对下游退化曲线一致，说明退化主要来自 ASR 的信息损失；(2) 单字错误在韩语里是独立的语义失败通道；(3) LALM 在 noisy 韩语 SQA 上击败 cascade。
- **对比方法/Baselines**: ASR-LLM cascade vs LALM 直读；LLM 部分跨多个模型扫一遍
- **借鉴意义**: 做 SpeechLLM、speech-in 直读 vs cascade 路线之争的人，这是难得的实证证据。结论"LALM 在噪声场景胜出"提供了"end-to-end speech LLM 对 cascade 真有优势"的小样本证据
- **锐评**: 分析型论文，没有方法贡献，但结论有用。两个潜在问题：(1) 用合成噪声做 SNR 扫描，与真实声学环境（混响、设备失真）对应不全； (2) "matched backbone LALM 击败 cascade" 中"matched"具体指 LALM 与 cascade 用的是相同 LLM 还是相近规模？若不是严格 controlled，这个结论的力度要打折。👀
