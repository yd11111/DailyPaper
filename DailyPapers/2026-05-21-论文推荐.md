### 1. Raon-OpenTTS: Open Models and Data for Robust Text-to-Speech
- **作者**: Eunseop Yoon, et al.
- **机构**: KRAFTON, Stanford University, University of Wisconsin-Madison, Ludo Robotics
- **链接**: [arXiv](https://arxiv.org/abs/2605.20830) | [PDF](https://arxiv.org/pdf/2605.20830)
- **来源**: 📄 arXiv 关键词检索
- 📒 **笔记**: [[Raon-OpenTTS]]

![](https://arxiv.org/html/2605.20830/extracted/figures/architecture.png)

- **核心方法**: 一个完整的开源 TTS 全家桶。输入文本 + 可选 reference audio，输出语音 waveform。架构走 [[DiT]]（Diffusion Transformer）路线，重点是配套放出大规模训练数据集（基于 LibriTTS / VoxPopuli / HiFiTTS2 / YouTube 重新整理）+ 完整训练脚本。评估在 WER / SIM / DNSMOS / CMOS / SMOS 五个维度上全面跑过，对标 [[CosyVoice]] / [[MaskGCT]] / [[VoxCPM]]
- **对比方法/Baselines**: 直接 baseline 是 [[CosyVoice]]、[[MaskGCT]]、[[VoxCPM]] 三家——都是当下开源 TTS 的扛把子。借鉴上明显来自 DiT-based 流派（参考 [[F5-TTS]] 一类）
- **借鉴意义**: KRAFTON 把全套数据 + 模型一起放出来这件事比模型本身有价值——做 TTS 复现的人长期被数据卡脖子，能用 CC-BY 协议拿到一份"干净"的训练集是稀缺资源。如果你在做 zero-shot TTS 或想 fine-tune 自家模型，这份 data 直接可以拿
- **锐评**: KRAFTON（游戏公司）也来卷 TTS 了，挺意外的。方法层面是 incremental——DiT-TTS 这条线 F5-TTS 早就探过；真正的卖点是数据。但要警惕："Open" 包不包含 commercial use 取决于 CC 协议细节，标题里的 "Robust" 在摘要里没看到具体怎么 robust（噪声？rare speakers？口音？）。等正文出来看

### 2. Synchronization and Turn-Taking in Full-Duplex Speech Dialogue Models
- **作者**: ASAPP Inc. & Universidad de Buenos Aires 联合
- **机构**: ASAPP Inc., USA; Departamento de Computación FCEyN, Universidad de Buenos Aires, Argentina
- **链接**: [arXiv](https://arxiv.org/abs/2605.20356) | [PDF](https://arxiv.org/pdf/2605.20356)
- **来源**: 📄 arXiv 关键词检索
- 📒 **笔记**: [[Synchronization-Turn-Taking]]

![](https://arxiv.org/html/2605.20356/extracted/figures/fdsds_framework.png)

- **核心方法**: 提出 **FDSDS（Full-Duplex Speech Dialogue System）评测框架**，专门拆解全双工模型的两件事：(1) **synchronization**——模型何时该说何时该听的内部状态对不对；(2) **turn-taking**——IPU、EOI（end-of-interruption）、PAD、Non-Hold 等真实对话事件的检测准确率。指标用 CKA（中心核对齐）量化模型内部表征对说话/听话的可分离性，外加 AUC/ROC 量化 turn-taking 决策
- **对比方法/Baselines**: 论文搭框架，应该会在多个开源全双工模型上跑（如 [[Moshi]]、[[LSLM]]、SyncLLM 等同期工作），但具体名单要看正文。method_names 没暴露具体被测模型
- **借鉴意义**: **如果你在做全双工 SLM，这是个直接能用的评测基准**。当前全双工评测最大的痛点是"我的模型说话自然吗"没法量化——这篇用 CKA 给"模型知不知道该说话"找了个内部指标，比单纯听 demo 强。配合 GitHub 开源即可对接
- **锐评**: 这篇真把全双工的"水下冰山"拆出来了——大多数论文只测对话流畅度（subjective），这篇直接测"模型对自己处于说/听状态的认知"。指标多得有点学术（CKA + AUC + ROC + IPU + EOI + PAD 一大堆），实际部署时你只关心其中 2-3 个；但作为研究工具是真的扎实。一个担心：ASAPP 是 contact center AI 公司，评测集大概率偏 customer service 场景，转到陪伴/教育领域得自己重做 fine-tune
- **🧪 锐评依据**：
  - `Claim: 真把全双工的"水下"拆出来评测` | `Evidence: method_names 含 'CKA', 'IPU', 'EOI', 'PAD', 'Non-Hold', 'AUC', 'ROC'；title 含 "Synchronization and Turn-Taking"` | `Confidence: 高`

### 4. DuplexSLA: A Full-Duplex Spoken Language Model with Synchronized Speech, Language, and Action
- **作者**: Multiple authors
- **机构**: Shanghai Jiao Tong University, University of New South Wales, Imperial College（以及 OpenBMB 等）
- **链接**: [arXiv](https://arxiv.org/abs/2605.20755) | [PDF](https://arxiv.org/pdf/2605.20755)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2605.20755/extracted/figures/duplexsla_arch.png)

- **核心方法**: 给全双工 SLM 加了第三个通道——**Action**。Speech-in/out + Language token + Action token 三路并行，用 FIFO 队列保证三路同步；底座 LLM 用 [[MiniCPM]]，TTS/ASR/VAD 串成处理链，加 PersonaPlex 数据集做训练。CPT (continual pre-training) → SFT → AT (action tuning) 三阶段训练。Per-Chunk 是它的同步粒度
- **对比方法/Baselines**: 拿 [[Step-Audio]] 当主要对比对象（method_names 直接出现）；底座选 MiniCPM 这条线对标 [[OmniFlatten]] / 同类 SLM
- **借鉴意义**: 把 "action" 单独建模这件事对做 voice agent / 语音助手的人有用——传统全双工模型只输出语音 + 文本，调用工具/产生 UI 操作得 prompt LLM 二次推理。这篇把 action 拉到 SLM 同等地位，理论上可以一步直出操作
- **锐评**: 想法很 sexy，但 "Synchronized Speech + Language + Action" 这个三路 FIFO 同步听起来很容易拍脑袋——实际跑起来 action 通道的 token rate 跟 speech token rate 差几个数量级（action 是 ms 级偶发，speech 是 50ms 一帧），FIFO 怎么调度细节没在 abstract 里说清。担心是 demo 跑得通但产品化时 action 频繁打架。Persona 名字（PersonaPlex / DuplexSLA / MiniCPM）一长串组合，警惕拼凑感
- **🧪 锐评依据**：
  - `Claim: action 通道与 speech token rate 量级不匹配，FIFO 调度细节存疑` | `Evidence: 领域常识——action 通常事件驱动稀疏，speech token 是连续帧；abstract 没披露 action rate` | `Confidence: 低`
  - `Claim: 底座 MiniCPM + Step-Audio 对比定位` | `Evidence: method_names 含 'MiniCPM', 'Step-Audio'` | `Confidence: 高`
  - `Claim: 三阶段训练 CPT/SFT/AT` | `Evidence: method_names 含 'CPT', 'SFT', 'AT'` | `Confidence: 中`

### 3. Mega-ASR: Towards In-the-wild² Speech Recognition via Scaling up Real-world Acoustic Simulation
- **作者**: Multiple authors
- **机构**: NTU, NUS, Shanghai AI Lab
- **链接**: [arXiv](https://arxiv.org/abs/2605.19833) | [PDF](https://arxiv.org/pdf/2605.19833)
- **来源**: 📄 arXiv 关键词检索
- 📒 **笔记**: [[MegaASR]]

![](https://arxiv.org/html/2605.19833/extracted/figures/mega_asr.png)

- **核心方法**: 解决 ASR 在真实噪声/远场/混响下泛化问题。提出 **MEGA** 大规模真实声学仿真 pipeline，配合 **WGPO（Weighted GRPO）+ DAPO** 两套 RL 训练策略，base 是 [[Kimi-Audio]] LLM-ASR。训练 + 测试都在 LibriSpeech / CommonVoice22 / WenetSpeech / AISHELL-1 / NOIZEUS（带噪）一起跑。Dual-Granularity 是细节设计
- **对比方法/Baselines**: 直接 baseline 是 [[Kimi-Audio]] 一类 LLM-ASR；声学仿真上对标传统的 RIR 卷积方法
- **借鉴意义**: "真实声学仿真" 是 ASR 长期掉链子的核心——所有人都知道 LibriSpeech 干净到不像真实世界。这篇如果仿真够真，能省下大量人工录数据的钱。WGPO + GRPO 的 RL 微调思路也适用于 [[Whisper]] 等开源 ASR 的下游适配
- **锐评**: 这篇的关键卖点是 "scaling up real-world acoustic simulation" + has_real_world=true（确实做了真实场景测试）。但要警惕"仿真"和"真实"之间的 gap——传统观点是仿真数据再像也救不了 OOD，必须配合 real recording。如果 MEGA 仿真真的能匹敌真录音，那就是好工作；如果只是又一个 reverb+noise 叠加，那就是包装。RL（WGPO/DAPO）部分有点蹭热度——ASR 这种 deterministic 任务用 RL 调比 SFT 优势能有多少存疑
- **🧪 锐评依据**：
  - `Claim: 做了真实场景测试不是只跑 LibriSpeech` | `Evidence: has_real_world=true；title 含 "In-the-wild²"；method_names 含 'NOIZEUS'（噪声评测集）` | `Confidence: 高`
  - `Claim: RL 调 ASR 优势存疑` | `Evidence: 领域常识——ASR 是 deterministic 任务，RL 收益通常不如 SFT 直接` | `Confidence: 低`
  - `Claim: 底座是 Kimi-Audio 类 LLM-ASR` | `Evidence: method_names 含 'Kimi-Audio'` | `Confidence: 高`

### 11. Codec-Robust Attacks on Audio LLMs
- **作者**: J. Monteuuis, Petit et al. (Qualcomm + UMass Amherst)
- **机构**: Qualcomm AI, University of Massachusetts Amherst
- **链接**: [arXiv](https://arxiv.org/abs/2605.20519) | [PDF](https://arxiv.org/pdf/2605.20519)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2605.20519/extracted/figures/codec_attack.png)

- **核心方法**: 攻击 Audio LLM 时，让对抗扰动**穿越音频 codec 压缩**仍然有效。常见 codec [[EnCodec]] / [[DAC]] 都会摧毁普通 PGD 对抗样本；这篇用 EoT (Expectation over Transformation) + AAC/PCM/WB/RVQ 多 codec 联合优化，专门生成 codec-robust 扰动。指标 SNR / STOI / PESQ / LSD 衡量扰动的可听性
- **对比方法/Baselines**: 传统 [[PGD]] 对抗攻击；之前的 [[AdvWave]] / [[AudioJailbreak]] 系列
- **借鉴意义**: 对做语音助手安全 / red-teaming 的人重要——证明了 codec 不是免费的防御层。同时反过来：做 codec 的人可以参考反推 codec 怎么设计更 robust against attack
- **锐评**: 攻防论文里偏方法扎实的一篇。亮点是揭示 codec 不能当防御；但 evaluation 通常局限于 single-turn 对抗，真实使用场景多轮交互攻击成功率会衰减。Qualcomm 出这篇有商业动机（音频压缩是它的强项），引用即可，不必精读
- **🧪 锐评依据**：
  - `Claim: 用 EoT + 多 codec 联合优化生成 robust 扰动` | `Evidence: method_names 含 'EoT', 'EnCodec', 'DAC', 'AAC', 'PCM', 'WB', 'RVQ'` | `Confidence: 高`
  - `Claim: 真实多轮交互成功率会衰减` | `Evidence: 领域常识——多轮对话会暴露攻击模式` | `Confidence: 低`
