# 方法论复盘 — 知识地图建设的幻觉问题（2026-05-26）

## 0. 起因与触发

2026-05-26 单日完成了一波密集的知识地图建设工作：
- 读 11 篇 TTS 综述，写 [[TTS-11篇综述综合-2026-05]] 元综合
- 新建 2 张地图（[[TTS-表示层地图]] / [[TTS-SpeechLM-Dialogue关系]]）
- 修订 4 张地图（[[TTS-技术路线图]] / [[TTS-核心挑战]] / [[TTS-评测体系]] / [[TTS-代表模型谱系]]）
- 重构 0-* 目录架构
- 改 paper-reader skill 加 R6 联动
- dogfood 三篇高重要性论文（[[StepAudio2.5]] / [[CosyVoice3]] / [[Qwen3-TTS]]）补 R6
- 21 条待回填地图条目

**本应是收尾的 dogfood 阶段连续两次产生幻觉**：
1. 把 Qwen3-TTS 标为 `unified-token-space` representation —— 实际 text/speech tokenizer 分离
2. 修正后又写"Qwen3-TTS warm start 必须 loss balancing 防止 catastrophic forgetting" —— 实际 Qwen3-TTS 训练时只对 speech token 做 loss，没有文本 loss

用户两次纠正后给出根因诊断：「**我现在发现一个重要的点，如果只根据现有的论文阅读报告来进行分析就很容易幻觉**」。进一步追问下，给出修复洞察：「**应该在读论文同时就把更新知识库需要的信息从论文原文中确认好**」。

## 1. 根因分析

### 1.1 表象：单点幻觉

dogfood 时把通用 ML 直觉填进 Qwen3-TTS 论文笔记"看起来缺失但应该有"的位置（warm start 应该有 loss balancing），是单点幻觉。

### 1.2 中层原因：二阶分析的信息丢失

更深一层：**任何基于已有论文笔记做的下游分析都建立在压缩信息上**，必然产生信息丢失型幻觉。

信息流：`论文原文 → [压缩 1: 精读笔记] → [压缩 2: 综述/地图] → [压缩 3: 元综述/趋势]`。
- 论文笔记是论文原文的 5-10% 压缩
- 二阶分析（dogfood R6 / 知识地图建设 / 周更 SOP）默认假设笔记够用，但**笔记不包含的所有原文细节就是幻觉滋生地**
- 看到对照表整齐时认知偏好让人填补缺失 cell（"这个位置应该是 X"）→ 这就是幻觉

### 1.3 根本原因：verify 责任错配

最深一层（用户的洞察）：**verify 责任的时序错配**。

- **旧工作流**（错的）：
  ```
  paper-reader 读论文 → 论文笔记（部分 verify，重点是核心方法/实验/结果）
                              ↓
  周更 SOP / 地图回填时 → 基于已有笔记做二阶分析（这时已离开原文）→ 幻觉
  ```
  问题：`verify 延迟到周更`这个设计本身是错的。时间越长，"读笔记 = 读原文"的错觉越强；二阶分析时再回头读原文成本高（多一次 WebFetch + 重新理解上下文），现实中常被跳过 → 直接基于摘要推断。

- **新工作流**（用户提出）：
  ```
  paper-reader 读论文 → 同时为知识库下游需求 verify 所有相关具体技术断言 → 笔记里所有具体技术信息都带 §X 来源
                                                                                  ↓
  地图回填 / dogfood R6 / 二阶分析 = 整合已 verified 信息，不做新断言 → 无幻觉
  ```

  关键：**verify 责任从二阶 skill 提前到 paper-reader 一次性完成**。

### 1.4 为什么这个错配如此普遍

paper-reader 当前模板（在引入 R6 之前）的设计目标是"写一份精读笔记"，不是"为下游知识库服务采集元数据"。所以：

- 笔记里"批判性思考""我的归纳""领域定位"等段是**笔者的二阶产物**——已经是基于论文的推断，不是论文事实复述
- 后续 skill 引用这些段时本质是引用"上一次读时的二阶判断"，不是论文本身
- 链式扩散：每一次基于上一次的二阶产物再做二阶分析，幻觉越积越深

## 3. 新工作流设计

### 3.1 核心原则

**verify 责任在 paper-reader 一次完成，不延迟**。论文笔记 = 论文原文 §X 直接 verify 过的元数据集合，不再是"压缩 + 笔者推断"。

### 3.2 paper-reader 的新职责

旧职责：写一份精读笔记。
新职责：精读 + **为知识库下游需求一次性 verify 所有相关具体技术断言**，每个断言带 §X 来源。

### 3.3 必须 verify 的"知识库元数据清单"

paper-reader 在读论文时，**除了精读笔记主体**，还要主动定位以下信息并标具体来源。verify 是**三层渐进**：

**Layer 1: 论文原文 §X**（首选，最快）
- WebFetch arXiv HTML 全文 → 定位章节 / 公式 / 表格 / 图
- 标记格式：`[§3.2]` / `[Eq.5]` / `[Tab.2]` / `[Fig.3]`

**Layer 2: GitHub 源码**（论文原文含糊或不足时**必须**查）
- 论文说 "我们用 X 方法" 但没说具体超参 → 查 `config.yaml` / `train.py` / `model_init.py`
- 论文说 "训练 loss 由 X 组成" 但没列公式 → 查 `loss.py` / `trainer.py`
- 论文说 "warm start from X" 但没说从哪个 checkpoint → 查 `init_weights()` / `pretrained_path`
- 论文说 "双 tokenizer" 但没说内部架构 → 查 `tokenizer/` 目录代码
- 标记格式：`[GitHub: <repo>/<path>:<line>]` 或 `[GitHub commit <SHA>]`

**Layer 3: 第三方实现 / 复现报告**（前两层都不够时，最弱）
- 当论文未开源 + 找不到第三方独立复现 → 显式标"无可靠来源 verify，仅论文 abstract 描述"

paper-reader 在读论文时，必须主动定位以下信息并标来源：

| 元数据维度 | verify 要求 | 写入位置 |
|---|---|---|
| **LM 参数初始化** | "从头训练 / 用 X 通用 LLM 初始化"，**论文不明 → 查 GitHub `init_weights/load_pretrained`** | frontmatter `lm_init: "warm-start from Qwen3-1.5B [§3.2; GitHub: qwen3_tts/model.py:42]"` |
| **训练 loss 设计** | "speech token loss only / 多任务 loss / 含文本 loss"，**论文不明 → 查 GitHub `loss.py/trainer.py`** | frontmatter `training_loss: "speech-token CE only, no text loss [§3.3 Eq.5; GitHub: trainer.py:128]"` |
| **Tokenizer 架构** | "text+speech 分离 / interleaved / 并行多 codebook"，**论文不明 → 查 GitHub `tokenizer/`** | frontmatter `tokenizer_arch: "separated text/speech tokenizers [§2.1 Fig.2; GitHub: tokenizer/spec.json]"` |
| **是否多任务训练** | 单任务 / 多任务，**模糊时查 GitHub training script** | frontmatter `multitask: false [§3.3; GitHub: train.py:55]` |
| **数据规模/构成** | 具体小时数 / 配对方式 / 语种比例，**模糊时查 GitHub `data_pipeline/`** | frontmatter `training_data: "500万h, 中英为主 [§4.1; GitHub: data_recipes/]"` |
| **关键 ablation 选择** | 哪些 ablation 真的做了 vs 论文未提 | 笔记 §"批判性思考-可复现性" |
| **后训练算法** | RLHF / DPO / DiffRO / 自定义 reward，**算法细节模糊时查 GitHub `rlhf/`** | frontmatter `post_training: "DiffRO [§3.4; GitHub: cosyvoice3/rlhf/diffro.py]"` |
| **Codec 内部细节** | RVQ 层数 / FSQ levels / 码本大小 / 帧率 | frontmatter `codec_detail: "RVQ 8层, code_size=1024 [GitHub: codec/config.yaml]"` |

每条都必须带 `[§X]` 或 `[Fig.X]` / `[Tab.X]` / `[Eq.X]` / `[GitHub: file]` 等具体来源。

### 3.4 R6 (🗺️/🔄) 在新工作流下的填法

旧填法（错）：基于已有笔记摘要 + 通用直觉推断"X 在哪条路线 / Y 是 cold/warm start"。
新填法（对）：直接消费 §3.3 的 verified 元数据。

例：
- 旧：`Qwen3-TTS 是 warm start [未 verify]`
- 新：`Qwen3-TTS 用 Qwen3 LLM 初始化 [§3.2]，训练时 speech-token loss only [§3.3 Eq.5]，文本能力 forget [§4 表 2 ablation]`

### 3.5 二阶 skill（paper-compare / paper-highlights / 元综述 / 地图回填）的新职责

新职责：**整合已 verified 元数据，不做新断言**。

- 整合时：直接 copy paper-note 里 §X 来源的元数据，保留 §X 标注
- 不做新断言：当二阶 skill 想说"X 是 Y" 但 paper-note 里没有这条 verified 元数据时，**禁止**做断言，必须：
  - 要么提议"先去 paper-reader 重读 Y 论文 verify 这一点"
  - 要么明示"未 verify，仅基于直觉推断"

### 3.6 工作流落地需要的 skill 改造

- [ ] **paper-reader/SKILL.md** 加新 Step "知识库元数据采集 + 三层 verify"（详见 §3.3 清单），列出每篇论文必须 verify 的字段 + 三层 fallback（论文原文 → GitHub 源码 → 第三方实现）
- [ ] **paper-note-template.md** frontmatter 新增 §3.3 列出的 metadata 字段（含 `[GitHub: <path>]` 来源标注）
- [ ] **paper-reader 自动化辅助**（可选）：写一个 helper 脚本 `fetch_github_code.py`，给定 arXiv ID 或论文标题 → 找 GitHub repo → 下载关键路径文件（README / config / model.py / trainer.py / loss.py）到本地缓存，paper-reader 直接 Read

### 5.1 进一步的局限识别（待跟进 todo，2026-05-26 补记）

用户在新工作流落地后又指出更深一层洞察：「**不一定，去开始做笔记的时候可能就引入了不合理、确定的信息**」。

也就是说，**三层 verify（论文 § / GitHub / 第三方）也不是银弹**——即便 paper-reader 严格按 §2.5 + §11 跑完，仍可能在以下环节引入幻觉：

| 环节 | 风险 |
|---|---|
| 对论文原文的**理解偏差** | 论文用词模糊时主观补全（如把"我们考虑了 X"理解为"我们用了 X"）|
| 对 GitHub 代码的**误读** | 不熟悉 framework 时把 hook 当主路径 / 把 deprecated 代码当现行 |
| 论文与代码**不一致**时的选择偏差 | 默认信论文导致幻觉；默认信代码可能漏 paper-only feature |
| **未明示的隐形假设**误纳入"verified" | 论文说"用 RVQ"，代码确实是 RVQ，但码本大小是从环境变量读、训练时被覆盖——单看代码看不到 |
| **采集元数据时的理解偏差扩散** | §2.5 元数据带 `[§3.2]` 来源，但写元数据时把 §3.2 内容理解错——"verified" 标签不等于"绝对正确" |

**这意味着**：所谓"已 verify"是**当下读懂的程度**，不是绝对真理。笔记应该被视为**"高于摘要、低于原文"** 的中间产物，**不是 ground truth**。下游使用时仍要警惕。

**待跟进的防御机制**（暂记 todo，不立即落地）：

- [ ] 笔记里所有"已 verify" 元数据后**附原文摘录**（不只是 `[§3.2]` 标记，而是引用原文关键句）—— 让二阶 skill 至少能看到原始 phrase 而非只读 Claude 的转译
- [ ] 笔记建立"**疑点清单**"区块——主动列出 Claude 自己不能 100% 确定的判断
- [ ] 重要论文（高频被引用进二阶分析的）应该建立 **第二人 review 机制**（用户人工 review 或换一个 Claude 会话独立 verify）
- [ ] 二阶 skill 在使用 `[已 verify §X]` 标签时应当 **probabilistic discount**——即便看到 verified 标签仍要保持 healthy skepticism

**但这些是"加固反幻觉防御"，不是"取消反幻觉防御"**。当前的三层 verify + R7 + §10 + §11 是基础设施，仍然必须做。新洞察提醒的是：**做了基础设施 ≠ 万无一失**。
