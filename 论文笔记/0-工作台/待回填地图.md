## 0. 用途

这是知识系统的**回流核心节点**。任何新论文 / 综述 / 概念进入 vault 后，应自动或半自动追加到这里。处理一条等于"基于新认知更新一组地图笔记"——这就是从论文库升级到知识系统的关键动作。

主链路：

```
DailyPapers → 论文层（自动）→ 概念层（自动）→ 待回填地图（半自动）→ 地图层（人工） → 阶段判断（人工）
```

**保留态度**：工作台容易变积压队列。建议每周固定时段（如周末 1 小时）清空。如果一周内无法消化，需要降低 DailyPapers 入库阈值或提高 review skip 比例。

## 1. 处理 SOP

### 日更 SOP（每天 < 5 分钟）

1. 看 [[DailyPapers/YYYY-MM-DD-论文推荐]]
2. 选择值得入库的论文 → 触发 paper-reader → 笔记写入对应 `1-15` 目录
3. paper-reader 自动追加条目到本工作台（**待 paper-reader skill 改造**，详见 [[笔记frontmatter规范]] §10）

### 周更 SOP（每周 30-60 分钟）

1. 打开本工作台，处理 `状态: 待处理` 的条目
2. 对每条：
   - 阅读论文笔记，确认 frontmatter 的 routes / problems / related_maps 字段是否准确
   - 打开 `related_maps` 里列出的每张地图，决定是否需要更新（写一段、补一行、修订一个判断、什么都不做）
   - 在论文笔记 frontmatter 标记 `map_backfilled: true` + `backfilled_at: <日期>`
   - 把本工作台对应条目标 `状态: 已处理 <日期>`
3. 如果某条目处理后发现需要新建概念笔记、对比报告或新地图笔记，**直接做**或转入相应 skill（paper-highlights / paper-compare）

### 月更 SOP（每月 1-2 小时）

1. 回看本月所有已处理条目，看哪些路线 / 问题被反复触及（频率 > 3）
2. 更新 [[TTS-代表模型谱系]] 加入本月重要新模型
3. 更新 [[TTS-趋势判断]] 修订过时判断
4. 季度时（每 3 个月）：写一份 `0-版本综述/<YYYY-Qx>-TTS阅读总结.md`

### 复审触发 SOP（半年一次）

参考 [[TTS-趋势判断]] §半年后回看清单，把"未验证"判断按本工作台里的新证据重新评估。

## 2. 工作台格式

每条待回填记录采用以下模板：

```md
## YYYY-MM-DD

### [[<笔记 wikilink>]]
- **domain**: <一级领域>
- **routes**: <路线标签 1>, <路线标签 2>
- **problems**: <问题标签 1>, <问题标签 2>
- **representations**: <表示标签>
- **建议回填到**：
  - [[<地图笔记 1>]] —— <具体补什么>
  - [[<地图笔记 2>]] —— <具体补什么>
- **状态**: 待处理 / 已处理 YYYY-MM-DD / 已 skip（理由）
```

按日期倒序排列（最新日期在上）。

## 3. 状态字段

| 状态 | 含义 | 处理 |
|---|---|---|
| `待处理` | 新进入，未 review | 周更 SOP 处理 |
| `已处理 <日期>` | 已完成地图回填 | 保留在工作台作为审计记录 |
| `已 skip（<理由>）` | 决定不回填（如：与已有判断完全重合、过于边缘、证据 low） | 保留作为决策记录 |

**重要**：处理完一条不要删除，保留作为知识演化记录。3 个月以上的已处理/已 skip 条目可移到子目录 `Archive/YYYY-MM/` 减少主文件长度。

### 元洞察 2：LLM 初始化策略 (warm start vs cold start) 是 Codec LM 路线内的关键分化轴

**触发**：dogfood CosyVoice3 + Qwen3-TTS 时发现两者表面差异（"独立 TTS" vs "LLM-native"）的本质在 LLM 参数初始化，不在 token 空间架构（2026-05-26 修正，二次修正）。

**精确分类（来自二次修正）**：

| 路线 | LM 初始化 | 训练 loss | 训练后是什么 | 代表 |
|---|---|---|---|---|
| **cold start 专用 LM** | 随机初始化 | 仅 speech token loss | 专用 TTS | [[CosyVoice]] 系列、[[VALL-E]] 系列、[[SeedTTS]]、[[IndexTTS2]] |
| **warm start 借用初始化** | 通用 LLM 参数 | 仅 speech token loss（**无文本 loss → 文本能力 forget**）| 专用 TTS（用更好的初始化）| [[Qwen3-TTS]] |
| **warm start 多任务保留** | 通用 LLM 参数 | 多任务 loss（保留文本/通用能力）| 通用 LLM + 模态扩展 | [[GLM-TTS]] 部分情况 |
| **多任务 SpeechLM** | 可 warm 可 cold | 多任务 loss（ASR+TTS+对话）| 统一 SpeechLM | [[StepAudio2.5]]、[[Moshi]] |
| **真 unified-token-space** | 通常 warm | 多任务 loss + token interleaving | text/speech 混合 LLM | Spirit-LM、Moshi（部分） |

**关键澄清**：之前混用了"warm start"和"保留通用能力"——**这是两个独立维度**：
- 是否 warm start：决定初始化质量
- 训练时是否含文本 loss：决定是否保留通用能力
- Qwen3-TTS 是 warm start + 无文本 loss → 借用初始化但不保留通用能力

**应补的回流**：
- [[TTS-技术路线图]] §路线 2 Codec LM —— **按上面 5 行表格新增 5 个子分化轴**
- [[TTS-代表模型谱系]] —— 把 Codec LM 大节点拆为对应子分支
- [[TTS-趋势判断]] §趋势 3 LLM-native —— 精确化定义：当前所谓"LLM-native"通常指 **warm start + speech-only loss**（既不是 unified-token-space，也不保留通用能力）
- [[笔记frontmatter规范]] —— 在 routes 枚举里加 `cold-start-codec-lm` / `warm-start-codec-lm` / `multitask-speechlm` 等更精细标签
- 未来考虑新建 [[_概念/5-Speech-LLM与AudioLM/LLM-初始化策略术语标准化.md]]

**状态**：待处理（这是**重要术语澄清**，影响 [[TTS-技术路线图]] 路线 2 + [[TTS-代表模型谱系]] + [[TTS-趋势判断]] + [[笔记frontmatter规范]]）
