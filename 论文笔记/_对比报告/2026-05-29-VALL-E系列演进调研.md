# VALL-E 系列演进专题调研

> 微软研究院(Furu Wei / Shujie Liu 组)的 codec-LM TTS 谱系:从开创范式 → 跨语言扩展 → 鲁棒/效率分叉 → 质疑离散化 → 三种表示分化。本报告以"每一代解决了上一代什么问题"为主线,辅以拆块速览矩阵。所有数字均溯源自对应笔记;笔记未记录的写"—"。

## 一句话结论

- **[[VALL-E]]**(2301.02111, 2023-01):把 TTS 重定义为"在 EnCodec 离散码上做条件语言建模",AR(第1层)+NAR(第2-8层),60K 小时训练实现 3 秒 prompt 零样本克隆。**读它 = 理解整个范式的起点。**
- **[[VALL-E-X]]**(2303.03926, 2023-03):把同一范式扩到**跨语言 / 零样本 S2ST**,用 Language ID 消除外语口音。**想做跨语言音色迁移看它。**
- **[[VALL-E R]]**(2406.07855, 2024-06):走**显式对齐**路线修鲁棒(推理期 phoneme 单调对齐)+ codec-merging 提速 60%+,副产物是韵律可控/VC。**想要鲁棒+可控、能接受 MFA 依赖看它。**
- **[[VALL-E2]]**(2406.05370, 2024-06):走**反对齐**路线——纯推理 trick RAS 治不稳定 + Grouped Code Modeling 沿时间轴分组提效,号称首个 human parity。**最可复用的洞察是 RAS(零训练成本修鲁棒)。**
- **[[MELLE]]**(2407.08551, 2024-07):**直接抛弃 VQ**,在连续 mel 空间做 AR + 变分 latent sampling,质疑"语音必须离散化才能做 AR"。**想探索 codec 之后的方向看它(起点)。**
- **[[FELLE]]**(2502.11128, 2025-02 · ACM MM 2025):在 MELLE 的连续 mel AR 上,**每个 AR step 内嵌 token-wise coarse-to-fine flow matching**,AR 管全局时序、flow 管局部精细——把"去 VQ"路线的质量补上去(SIM-o 全面超 MELLE,cross MOS 4.157>GT 4.043)。**想看连续表示怎么提质看它。**
- **[[PALLE]]**(2504.10352, 2025-04 · ACM MM 2025):换**第三种表示**(S3Tokenizer 语义 token)+ MaskGIT 式骨干,核心创新 **Pseudo-Autoregressive(PAR)** 把 AR/NAR 统一成"固定步 + 动态长 span",两阶段(PAR 草稿 + 置信度 NAR 精修),RTF 低至 0.06。**想要极低延迟 + AR/NAR 统一调度看它。**

> 该读哪个取决于目的:**学范式**读 VALL-E;**借一个能立刻用的工程 trick**读 VALL-E 2 的 RAS;**找鲁棒性思路**对比 R(对齐) vs 2(采样)两条哲学;**赌去离散化方向**看 MELLE→FELLE(连续 mel);**追低延迟/统一 AR-NAR**看 PALLE 的 PAR。

## 演进主线:每一代解决了什么

### ① VALL-E(2023-01)— 立范式
把中间表示从 [[Mel-Spectrogram]] 换成 [[EnCodec]] [[RVQ]] 离散码,把 TTS 从"连续信号回归"变成"语言建模",首次证明 TTS 也吃 data scaling(60K 小时)并具备 in-context learning(3 秒 prompt 零样本)。
**留下的坑**:① AR 注意力隐式对齐 → 漏读/重复/错读(鲁棒性);② AR 跑满 75Hz 序列 → 推理慢(论文未报 RTF);③ 仅英文;④ AR/NAR 两个独立模型;⑤ 必须先把语音离散化成 token。

### ② VALL-E X(2023-03)— 拓广度(跨语言)
把坑 ③ 的一部分补上:用 LibriLight(英) + WenetSpeech(中) 两个**单语**语料训出跨语言能力,无需同一说话人的双语数据。关键设计 **Language ID**:加在声学 token 嵌入上,以牺牲少量音色相似度为代价大幅压制外语口音(accent 2.55→4.10)。还接了 SpeechUT 做零样本 S2ST。
**仍未解决**:坑 ①②(鲁棒性、效率)原样继承;只验证了中英双语,中文方向明显弱于英文(WER 8.52 vs 4.07)。

### ③ 2024-06 的分叉 — VALL-E R vs VALL-E 2:同攻"鲁棒+效率",两种哲学
这是整个系列最值得对照的一对:**同一个月、同一实验室**,都瞄准 VALL-E 的坑 ①②,但走相反路线。

| | [[VALL-E R]] | [[VALL-E2]] |
|---|---|---|
| 修鲁棒的手段 | **加对齐信号**:推理期 phoneme 单调对齐(训练用 MFA 强制对齐) | **不加对齐**:RAS 按重复率切换 nucleus/random sampling |
| 提效率的手段 | codec-merging(第1层 2× 下采样到 37.5Hz) | Grouped Code Modeling(沿时间轴分组,序列→1/G) |
| 对数据的要求 | 需要 MFA 逐帧对齐 | 只需句级语音-文本配对(刻意避开对齐/duration) |
| 代价 | 依赖外部对齐器,低资源语种迁移成本高 | G≥4 后细粒度依赖被削、SIM/WER 退化 |

> **核心张力**:R 认为"补上显式对齐才能根治鲁棒",2 认为"一个采样 trick 就够、别污染数据管线"。两者都把对齐/提速做成**推理期或轻量改动**,不重训 codec。R 的 MA 是鲁棒性主因(去掉就退回 VALL-E 的 WER 2.37);2 的 RAS 让模型能在极小 top-p 下稳定解码,从而拿到低于 GT 的 WER。

### ④ MELLE(2024-07)— 质疑地基(去 VQ)
前四代都建立在"语音先离散化成 token"(坑 ⑤)这个假设上。MELLE 直接拆掉它:decoder-only Transformer **在连续 mel 空间自回归**,用 latent sampling module(变分采样)替代 VQ 的离散瓶颈,规避码本坍塌与信息损失。代表"codec 之后"的探索方向。
> ⚠️ MELLE 的本地笔记是**简版(Lite note)**,只记录了定性方法,未记录具体 WER/SIM 数字(原文仅称"与 VALL-E 系列可比")。下方矩阵中 MELLE 的指标按规则标"—"。

### ⑤ FELLE(2025-02)— 给"去 VQ"路线补质量
MELLE 只证明了连续 mel AR **可行**,但质量/相似度未拉满。FELLE 在 MELLE 的连续 mel AR 上,**每个 AR step 内嵌一个小型 token-wise coarse-to-fine flow matching**:AR 提供全局序列结构,flow matching 提供局部精细度,两者互补。结果 SIM-o 全面超 MELLE(continuation 0.513 vs 0.480、cross 0.619 vs 0.591),cross-sentence MOS 4.157 甚至超过 GT 4.043。
**意义**:坐实"连续表示 + AR"不是死胡同——MELLE 开路、FELLE 接力,混合 flow matching 是连续路线提质的有效补丁。
> ⚠️ FELLE 本地也是**简版笔记**,训练数据规模/开源状态未记录,矩阵相应位标"—";其 WER 用 **WER-C** 口径,与 VALL-E 系不同,跨论文不可比。

### ⑥ PALLE(2025-04)— 换第三种表示 + 统一 AR/NAR
前面所有工作的表示要么是 EnCodec **声学 token**(VALL-E 系),要么是**连续 mel**(MELLE/FELLE)。PALLE 走第三条:用 CosyVoice 2 的 **S3Tokenizer 语义 token**(25Hz 离散但语义),骨干换成 **MaskGIT 式双向 masked transformer**。核心创新 **Pseudo-Autoregressive(PAR)**:把 AR 的"固定步/每步 1 token"与 NAR 的"单步/全长"统一成**"固定步 + 动态长 span"**——保留从左到右的时序归纳偏置,又能并行解码。两阶段:Stage 1 PAR 出草稿,Stage 2 置信度引导 NAR 精修。
**最硬的证据是 Tab.3 同骨干受控对比**(同数据/同 tokenizer/同骨干,唯一变量是范式):PAR 较 AR 降 36% WER 且约 4× 快,较 NAR 降 43% WER 且约 2× 快;两阶段 PALLE 在 LibriTTS 上 RTF 低至 0.06。
> ⚠️ 但仅 **LibriTTS ~580h 小数据**训练,与 Emilia 大数据训练的 F5-TTS/MaskGCT 跨行比不完全公平,"领先"宜限定在"小数据 + 低延迟"约束;两份独立 177M 权重(部署 ~2×);依赖外部 CosyVoice 2 detokenizer;未见官方开源。

## 关键差异(超越矩阵)

1. **鲁棒性的两条路**:VALL-E R = 显式对齐(MA,需 MFA);VALL-E 2 = 纯采样(RAS,零训练成本)。RAS 是整个系列**最可迁移**的工程洞察——任何 codec-LM 都能直接套用。
2. **效率的多条路**:R 在 **codec 侧**降帧率(codec-merging);2 在 **LM 侧**重组序列(Grouped Code Modeling);PALLE 直接换 **解码调度范式**(PAR,把 AR/NAR 统一成动态 span,RTF 0.06)。三者互补——前两者不动 codec 权重、可叠加,PALLE 则是另起骨干。
3. **对"对齐/duration"的态度**:R 拥抱对齐(更可控、可做 VC);2 刻意回避(保持数据管线极简);PALLE 用一个线性时长估计(Eq.11,实测 0.9–1.3× 都稳健),介于两者之间。
4. **表示的三分天下**:到 2025 年,VALL-E 谱系分化出**三条表示路线**——离散声学 token(VALL-E 系)、连续 mel(MELLE→FELLE)、离散语义 token(PALLE)。这比单纯的"离散 vs 连续"更细;每条路线的 SIM 上界由其表示的重建质量锁死。
5. **"AR 质量 + NAR 速度"的两种合一**:VALL-E 2 用 Grouped Code Modeling 在 AR 内塞并行(组内非自回归);PALLE 用 PAR 直接把 AR/NAR 统一成"固定步 + 动态 span"。都想兼得两者,但 PALLE 更激进地重定义了生成调度。
6. **评测口径**:VALL-E 2 的 "human parity" 仅在 in-domain LibriSpeech 部分指标成立,out-of-domain VCTK 客观 SIM 全面低于 GT;PALLE 的"领先"则受限于小数据 + 低延迟约束。两者的强主张都需读可信度分层后再引用。

## 各自的亮点(值得借鉴)

### [[VALL-E]]
- 范式开创:TTS = 条件 codec 语言建模,直接催生整条谱系及 SeedTTS/MaskGCT 等外部工作。
- AR/NAR 分工:第1层 RVQ 信息量最大用 AR 保连贯,2-8 层用 NAR 并行——契合 RVQ 残差结构。

### [[VALL-E-X]]
- Language ID 加法即可分离"语言特征 vs 说话人特征",消融揭示了口音-相似度的 trade-off 本质。
- code-switch / 情感保持是无监督涌现,印证大规模 ICL 的泛化。

### [[VALL-E R]]
- 把经典单调对齐迁到 **decoder-only 的推理期**,解决了单调注意力只能用于 encoder-decoder 的兼容性难题,且训练几乎零额外负担。
- codec-merging 是纯推理期 trick,Tab.5 给出"只合第一层"的明确甜点;MA 与 codec-merging 正交可叠加。

### [[VALL-E2]]
- **RAS**:不改训练、不增延迟,把 single-sampling WER 从 3.1 降到 1.5,可迁移到任何 codec-LM。
- **Grouped Code Modeling**:把"降帧率"从 codec 设计问题转成 LM 侧序列重组,G=2 近乎白拿 2× 加速且不掉点。
- 数据需求极简:不要 forced-alignment、不要 duration、不要额外参考音频。

### [[MELLE]]
- 证明"语音不必离散化也能做 AR",用变分 latent sampling 替代 VQ 离散瓶颈,绕开码本坍塌——为 codec-free TTS 提供可行样本。

### [[FELLE]]
- **token-wise coarse-to-fine flow matching**:把 flow matching 嵌进 AR 的每一步,AR 管全局序列、flow 管局部精细——证明连续 mel AR 可继续提质。
- SIM-o 全面超 MELLE,cross-sentence MOS 4.157 超过 GT,坐实"去 VQ"路线值得继续投入。

### [[PALLE]]
- **PAR 范式**:用"时间步 × 每步长度"二维把 AR/NAR/PAR 统一,"固定步 + 动态长 span"是干净的中间地带(Fig.1 直观)。
- **Tab.3 同骨干受控对比**设计干净(单变量=范式),PAR 双优(WER + 速度)证据是全文最硬。
- 效率收益实在:RTF 0.05–0.06,远低于 AR 的 0.21、CosyVoice 2 的 0.45;且诚实报告了联合多任务失败的负结果。

## 各自的硬伤

- **[[VALL-E]]**:AR 鲁棒性差(漏/重/错读);仅英文;未报 RTF;AR+NAR 两段未统一。
- **[[VALL-E-X]]**:仅中英双语;中文方向明显弱;评测集偏小(EMIME 仅 350 样本);基线 YourTTS 偏弱,缺与 SeamlessM4T 等强基线对比。
- **[[VALL-E R]]**:仅 960h 英文读书短句;依赖 MFA;**代码未开源**;主观评测薄弱(置信区间重叠);提速对比挑了最有利的自实现 VALL-E(10.27s)而非引用版(6.2s)。
- **[[VALL-E2]]**:human parity 主张过强(VCTK 未达、无显著性检验、CMOS +0.033 在噪声量级);**不开源**;域窄(英文读书);SIM 被 EnCodec 重建上界锁死;NAR 仍跑 7 次贪心。
